## 3. 权威性与冲突解决

| 维度 | 权威 | 说明 |
|---|---|---|
| 设计深度与架构决策 | **V2.0 设计文档集** | 用户 Prompt 明确"所有后续设计必须遵守本Prompt中的架构约束" |
| V2.0 与 V1.2 冲突 | **以 V2.0 为准** | 关键 supersession 见下 |
| 开发顺序（Phase 1-9）与冻结技术栈 | V1.2 §11 | 代码推进顺序仍以 V1.2 为准 |
| 当前代码骨架 | `docs/architecture.md` | Phase 0 已落地结构 |

**关键 supersession（V2.0 覆盖旧决定）：**

1. **Conversation ID = 系统UUID**，不依赖 Boss ID（V1.2 §12 P0 的"Boss ID+UUID"作废）；`external_chat_id` 仅作同步锚点。
2. **数据库目标态 14 表**（含 settings/hrs/resume_summaries/memory/task_checkpoint_index），超越 Phase 0 已建 9 表；迁移见 doc 09 §9。
3. **LangGraph Checkpoint 用 AsyncPostgresSaver 自管**，不自建 checkpoint 表；业务侧仅 `task_checkpoint_index` 做 task↔thread 映射。
4. **Approval 属 Runtime**，20s 超时由后端定时器触发 `Command(resume="timeout")`，不经端点。
5. **MinIO + Docker Compose** 由"待确认"定为 V1 纳入。
6. **MCP 仅 stdio**（非 HTTP/SSE），不自建 Browser Client。
7. **双同步器**（Conversation Sync + Message Sync），取消 Resume Sync。
8. **Goal-Oriented Skill**：Skill 不写 selector/DOM；DOM 变化靠 read_page 重定位 ref。

## 5. 关键架构决定摘要

| 决定 | 文档 | 理由 |
|---|---|---|
| Agent -> Skill -> MCP，不直接操作浏览器 | 02 §16 | 解耦；Skill 无 selector 抗 DOM 变化 |
| MCP 一律 stdio | 02 §6 / 07 | 本地 Agent 管 Server 生命周期，不暴露端口 |
| DB 为真实数据源 | 02 §9.3 / 13 | LLM 读 DB 不读 DOM，解耦浏览器变化 |
| 单任务执行 + 事件驱动 | 04 §8 | 严格串行，避免并发冲突 |
| Conversation ID = 系统UUID | 09 §5.5 / 13 | 解耦平台；1 岗位 1 会话 |
| thread_id = conversation.uuid | 04 §9 / 09 | 简化 LangGraph checkpoint key |
| Checkpoint 用 AsyncPostgresSaver | 04 §9 / 09 §8 | 避免与 LangGraph 版本耦合 |
| Approval：interrupt() + Command(resume) | 06 / 14 | functional interrupt 天然支持 decision 注入 |
| 20s 超时由后端定时器触发 | 14 §4.3 | 不经端点，避免与用户响应竞争 |
| 监听四态机（idle/monitoring/paused/stopped） | 04 §7.2 / 11 | 落实"插件关继续/浏览器关停/主动关彻底停" |
| MV3 保活三层 | 11 §7 | Port keepalive + alarms 脉冲 + 后端心跳超时 |
| 两层 Retry | 06 / 15 | RetryPolicy 瞬时层 + error_recovery 恢复层；规则违反不重试 |
| Redis Stream 4 路优先级 | 04 §6 | Stream 无原生优先级，分流实现 |
| 双同步器 + 取消 Resume Sync | 13 | 职责分离；简历用户上传不抓取 |
| settings 独立表 | 09 §5.2 | 分组校验/版本化/分域 PUT |
| backend/worker V1 合并、生产拆分 | 16 §9 | 简化部署，代码可拆分 |
