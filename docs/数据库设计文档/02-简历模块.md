# 02 · 简历模块

## 模块说明

简历元数据与简历向量化分离设计：**`resumes` 只存元数据（文件、文本、状态）**，**`resume_summaries` 存结构化摘要 + 512 维向量**（多版本）。`embedding` 用 `pgvector` 存储句向量，模型为 `bge-small-zh-v1.5`（维度 512），用于语义匹配与长期记忆检索。`file_key` 指向 MinIO 对象。

## 表总览

| 表名 | 说明 | 主键 | 关键约束 |
|------|------|------|----------|
| `resumes` | 简历元数据 | id | — |
| `resume_summaries` | 简历摘要 + 向量（多版本） | id | UNIQUE(resume_id, version) |

---

## 表 1：`resumes`

> 简历模型。`embedding` 已迁移至 `resume_summaries`，此处保留兼容（逐步废弃）。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `user_id` | BIGINT | N | — | 所属用户，外键 |
| `name` | VARCHAR(100) | Y | — | 简历名称 |
| `version` | INTEGER | N | `1` | 版本号，支持多版本简历（迁移 0002 新增） |
| `file_key` | VARCHAR(255) | Y | — | MinIO 对象 key |
| `file_url` | VARCHAR(500) | Y | — | 可访问 URL |
| `content` | TEXT | Y | — | 解析后的纯文本，用于向量化与 Agent 引用 |
| `embedding` | VECTOR(512) | Y | — | **已废弃**，兼容保留；迁移至 `resume_summaries` |
| `is_default` | BOOLEAN | N | `false` | 是否为默认简历 |
| `status` | VARCHAR(20) | N | `'active'` | 状态：`draft` / `active` / `archived`（迁移 0002 新增） |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间（TimestampMixin） |
| `updated_at` | TIMESTAMPTZ | N | `now()` | 更新时间（TimestampMixin） |

### 索引

| 索引名 | 类型 | 列 |
|--------|------|----|
| `ix_resumes_user_id` | NORMAL | `user_id` |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `ck_resumes_status` | CHECK | `status IN ('draft','active','archived')` |
| `fk_resumes_user_id` | FOREIGN KEY | `user_id → users.id` |

### 关联关系

- **N:1** → `users`（`user_id`）
- **1:N** → `resume_summaries`（`resume_summaries.resume_id`，CASCADE）

### 备注

- `embedding` 列**保留但不建议写入**：新向量一律写 `resume_summaries`，读语义匹配走新表。
- 多版本策略：每次简历更新新建一个 version，保留历史（`is_default` 标识当前生效版）。
- 状态机：`draft`（草稿）→ `active`（生效）→ `archived`（归档）。

---

## 表 2：`resume_summaries`

> 简历摘要与向量。`(resume_id, version)` 唯一；新增摘要时 version 递增，旧版本保留。`embedding` 维度 512（`bge-small-zh`），ivfflat 索引在 DB 层创建。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `resume_id` | BIGINT | N | — | 所属简历，外键，CASCADE 删除 |
| `version` | INTEGER | N | `1` | 版本号，与 resume_id 联合唯一 |
| `summary` | TEXT | N | — | 结构化摘要（LLM 生成，供 Agent 引用） |
| `embedding` | VECTOR(512) | N | — | 512 维向量（bge-small-zh），用于语义匹配 |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间 |

### 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| `ix_resume_summaries_resume` | NORMAL | `resume_id` | FK 反查 |
| `ix_resume_summaries_embedding` | IVFFLAT（向量） | `embedding` | `vector_cosine_ops`，`WITH (lists = 100)` |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `uq_resume_summary_resume_version` | UNIQUE | `(resume_id, version)` 唯一 |
| `fk_resume_summaries_resume_id` | FOREIGN KEY | `resume_id → resumes.id`，`ON DELETE CASCADE` |

### 关联关系

- **N:1** → `resumes`（`resume_id`，CASCADE）

### 备注

- 该表**无 `updated_at`**：摘要与向量为不可变快照，更新 = 新增版本行。
- 向量索引为 `ivfflat`（近似最近邻），数据量较小时可先建，`lists=100` 为迁移中固定值；生产数据量增长后可评估换 `hnsw`。
- 迁移 0002 STEP 4.2 用 `resumes.content` 前 1000 字符占位生成 v1 摘要（真实摘要需后续 LLM 重跑）。
