# 05 · 任务与执行模块

## 模块说明

Agent 系统的调度核心：`tasks` 是任务主表（带状态机与优先级），`task_checkpoint_index` 桥接 Task 与 LangGraph Checkpoint，`execution_logs` 是 append-only 执行日志。LangGraph 的 Checkpoint 表（`checkpoints` / `checkpoint_writes` / `checkpoint_blobs`）由 `AsyncPostgresSaver` 自动创建管理，业务侧不直接操作。

## 表总览

| 表名 | 说明 | 主键 | 关键约束 |
|------|------|------|----------|
| `tasks` | Agent 任务 | id | CHECK(status)、CHECK(priority) |
| `task_checkpoint_index` | Task ↔ Checkpoint 索引 | id | — |
| `execution_logs` | 执行日志（append-only） | id | — |

---

## 表 1：`tasks`

> 任务模型。状态机：`pending → running → waiting_approval / recovering → succeeded / failed / canceled`。规则：一次执行一个 Agent 任务；多任务进入 Redis Stream 队列。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `user_id` | BIGINT | N | — | 所属用户，外键 |
| `type` | VARCHAR(50) | N | — | 任务类型（见备注） |
| `status` | VARCHAR(30) | N | `'pending'` | 状态机，CHECK 约束（见下） |
| `thread_id` | UUID | Y | — | 绑定的 Thread（= conversation.uuid），LangGraph Checkpoint 锚点 |
| `conversation_id` | BIGINT | Y | — | 关联会话，外键 |
| `job_id` | BIGINT | Y | — | 关联岗位，外键 |
| `priority` | VARCHAR(5) | N | `'P2'` | 优先级：`P0`（最高）~ `P3`（最低），CHECK 约束 |
| `payload` | JSONB | Y | — | 任务输入 |
| `result` | JSONB | Y | — | 任务输出 |
| `error` | TEXT | Y | — | 错误信息 |
| `retry_count` | INTEGER | N | `0` | 已重试次数 |
| `max_retries` | INTEGER | N | `2` | 最大重试次数（迁移 0002 由 3 改为 2） |
| `scheduled_at` | TIMESTAMPTZ | Y | — | 计划执行时间 |
| `started_at` | TIMESTAMPTZ | Y | — | 实际开始时间 |
| `completed_at` | TIMESTAMPTZ | Y | — | 完成时间 |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间（TimestampMixin） |
| `updated_at` | TIMESTAMPTZ | N | `now()` | 更新时间（TimestampMixin） |

### 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| `ix_tasks_status` | NORMAL | `status` | 按状态捞任务（调度扫描） |
| `ix_tasks_user_status` | NORMAL | `(user_id, status)` | 用户任务列表 |
| `ix_tasks_user_id` | NORMAL | `user_id` | FK 反查 |
| `ix_tasks_thread_id` | NORMAL | `thread_id` | 断点续跑按 thread 定位 |
| `ix_tasks_priority_scheduled` | NORMAL | `(priority, scheduled_at)` | 优先级调度队列扫描 |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `ck_tasks_status` | CHECK | `status IN ('pending','running','waiting_approval','recovering','succeeded','failed','canceled')` |
| `ck_tasks_priority` | CHECK | `priority IN ('P0','P1','P2','P3')` |
| `fk_tasks_user_id` | FOREIGN KEY | `user_id → users.id` |
| `fk_tasks_conversation_id` | FOREIGN KEY | `conversation_id → conversations.id` |
| `fk_tasks_job_id` | FOREIGN KEY | `job_id → jobs.id` |

### 关联关系

- **N:1** → `users`、`conversations`、`jobs`
- **1:N** → `approvals`（`approvals.task_id`）、`task_checkpoint_index`（CASCADE）、`execution_logs`

### 备注

- `type` 任务类型（代码注释约定）：`proactive_job`（主动找岗）/ `proactive_chat`（主动打招呼）/ `hr_reply`（HR 消息回复）/ `approval_resume`（投递确认）/ `sync`（同步）/ `recovery`（恢复）。无 CHECK 约束。
- `status` 状态机：
  ```
  pending → running → waiting_approval ─┬→ succeeded
                                └→ recovering → running（断点续跑）
  running / pending ──────────────→ failed / canceled
  ```
- `thread_id` 指向 `conversations.uuid`，LangGraph 断点续跑入口据此定位。
- 迁移 0002 将状态旧值大写改小写、`WAITING_HR → waiting_approval`、`COMPLETED → succeeded`、`CANCELLED → canceled`，并新增 `recovering`；`max_retries` 默认值 3 → 2。

---

## 表 2：`task_checkpoint_index`

> Task-Checkpoint 索引模型。业务侧不直接操作 LangGraph Checkpoint 表，本表为轻量索引，桥接 `task_id` 与 `thread_id/checkpoint_id`，便于：按 task_id 查询最近 Checkpoint、清理策略（终态保留最近 N 个）、断点续跑入口定位。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `task_id` | BIGINT | N | — | 关联任务，外键，CASCADE 删除 |
| `thread_id` | UUID | N | — | LangGraph thread_id（= conversation.uuid） |
| `checkpoint_id` | VARCHAR(100) | Y | — | LangGraph checkpoint_id（字符串标识） |
| `status` | VARCHAR(20) | N | — | `active`（任务进行中）/ `terminal`（任务终态） |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间 |

### 索引

| 索引名 | 类型 | 列 |
|--------|------|----|
| `ix_chk_task` | NORMAL | `task_id` |
| `ix_chk_thread` | NORMAL | `thread_id` |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `fk_task_checkpoint_index_task_id` | FOREIGN KEY | `task_id → tasks.id`，`ON DELETE CASCADE` |

### 关联关系

- **N:1** → `tasks`（`task_id`，CASCADE）

### 备注

- **该表无 `updated_at`**：一条索引记录代表一次 Checkpoint 注册/终态标记，不可变快照。
- `status` 无 CHECK 约束，代码注释约定 `active` / `terminal`。
- LangGraph 自动维护的三张表（`checkpoints` / `checkpoint_writes` / `checkpoint_blobs`）不在此文档范围，由框架创建。

---

## 表 3：`execution_logs`

> 执行日志模型（append-only）。字段依据技术栈文档：`task_id / node / tool / input / output / error`。额外加 `latency_ms` 便于性能分析。日志只追加，不混入 `updated_at`。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `task_id` | BIGINT | N | — | 关联任务，外键 |
| `trace_id` | VARCHAR(64) | N | `''` | 全链路追踪 ID（迁移 0002 新增） |
| `node` | VARCHAR(100) | Y | — | LangGraph 节点名：`job_analyze` / `response_planner` / `tool_executor` 等 |
| `skill` | VARCHAR(100) | Y | — | Skill 名（区分 Skill 与底层 Tool，迁移 0002 新增） |
| `tool` | VARCHAR(100) | Y | — | Tool 名 |
| `input` | JSONB | Y | — | 节点输入 |
| `output` | JSONB | Y | — | 节点输出 |
| `error` | TEXT | Y | — | 错误信息 |
| `latency_ms` | INTEGER | Y | — | 节点耗时（毫秒） |
| `created_at` | TIMESTAMPTZ | N | `now()` | 日志时间 |

### 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| `ix_execution_logs_task_created` | NORMAL | `(task_id, created_at)` | 按任务查执行轨迹 |
| `ix_execution_logs_trace_id` | NORMAL | `trace_id` | 全链路追踪反查 |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `fk_execution_logs_task_id` | FOREIGN KEY | `task_id → tasks.id` |

### 关联关系

- **N:1** → `tasks`（`task_id`）

### 备注

- **append-only 设计**：无 `updated_at`，禁止 UPDATE；只 INSERT。数据量大时应考虑分区/归档策略（按 `created_at`）。
- `trace_id` 跨 `execution_logs`、应用日志、WebSocket 推送打通，是全链路排查主键（doc 15 可观测）。
- 写日志不可成为主链路瓶颈：高频节点写日志应走批量/异步，避免阻塞 Agent 主流程。
