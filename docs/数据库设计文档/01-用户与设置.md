# 01 · 用户与设置模块

## 模块说明

承载用户基本信息与用户级配置。**权威配置在 `settings` 表**，`users.settings` 字段是历史 JSONB 兼容缓存层（迁移 0002 已做数据回填，后续新代码应读写 `settings` 表）。

## 表总览

| 表名 | 说明 | 主键 | 关键约束 |
|------|------|------|----------|
| `users` | 用户 | id | UNIQUE(email) |
| `settings` | 用户配置键值对 | id | UNIQUE(user_id, category, key) |

---

## 表 1：`users`

> 用户模型。API Key 以加密形式存储，禁止明文落库。LLM 配置为用户级覆盖项，可空时走全局默认。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键，BIGSERIAL |
| `email` | VARCHAR(255) | N | — | 登录邮箱，唯一 |
| `nickname` | VARCHAR(100) | Y | — | 昵称 |
| `password_hash` | VARCHAR(255) | Y | — | 密码哈希；Phase 2 接 JWT 时填充 |
| `llm_provider` | VARCHAR(50) | Y | — | 用户级 LLM 提供商（覆盖全局默认） |
| `llm_base_url` | VARCHAR(500) | Y | — | 用户级 LLM base_url（迁移 0002 新增） |
| `llm_api_key_encrypted` | VARCHAR(500) | Y | — | 加密后的 API Key，禁止明文 |
| `llm_model` | VARCHAR(100) | Y | — | 用户级 LLM 模型名（迁移 0002 新增） |
| `settings` | JSONB | N | `'{}'::jsonb` | 灵活设置项缓存；**已废弃，兼容层** |
| `is_active` | BOOLEAN | N | `true` | 账号是否激活 |
| `last_login_at` | TIMESTAMPTZ | Y | — | 最近登录时间 |
| `bio` | TEXT | Y | — | 用户备注/简介，供 Agent 个性化回复 |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间（TimestampMixin） |
| `updated_at` | TIMESTAMPTZ | N | `now()` | 更新时间，自动刷新（TimestampMixin） |

### 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| `ix_users_email` | UNIQUE | `email` | 登录唯一性 |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `uq_users_email` | UNIQUE | `email` 唯一 |
| `pk_users` | PRIMARY KEY | `id` |

### 关联关系

- **1:N** → `settings`（`settings.user_id`，CASCADE）
- **1:N** → `resumes`（`resumes.user_id`）
- **1:N** → `jobs`、`hrs`、`conversations`、`messages`、`tasks`、`approvals`、`sync_records`、`memory`

### 备注

- `email` 同时建了 UNIQUE 约束与 UNIQUE 索引（约束用于逻辑保证，索引用于快速查找，二者在 PG 中实际复用同一索引）。
- `settings` 列保留只为兼容，权威入口为 `settings` 表；迁移 0002 STEP 4.1 已把旧 JSONB 逐 key 拆入 `settings`（`category='legacy'`）。

---

## 表 2：`settings`

> 设置模型（独立表，替代 `users.settings` JSONB）。按 `category + key` 存储用户配置，支持分组校验、按字段版本化、API 分域 PUT。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `user_id` | BIGINT | N | — | 所属用户，外键 |
| `category` | VARCHAR(30) | N | — | 配置域，CHECK 约束限定枚举 |
| `key` | VARCHAR(100) | N | — | 配置键名 |
| `value` | JSONB | N | — | 配置值，支持 string/number/bool/object 等类型化值 |
| `updated_at` | TIMESTAMPTZ | N | `now()` | 最近更新（非 Mixin，只有 updated_at 无 created_at） |

### 索引

| 索引名 | 类型 | 列 |
|--------|------|----|
| `ix_settings_user` | NORMAL | `user_id` |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `uq_settings_user_cat_key` | UNIQUE | `(user_id, category, key)` 唯一 |
| `ck_settings_category` | CHECK | `category IN ('llm','job_rule','agent','reply_style')` |
| `fk_settings_user_id` | FOREIGN KEY | `user_id → users.id`，`ON DELETE CASCADE` |

### 关联关系

- **N:1** → `users`（`user_id`，CASCADE）

### 备注

- `category` 与 API 路由一一对应（doc 10 分域 PUT）：
  - `llm`：LLM 提供商、base_url、model、api_key（**加密后**存 value JSONB）
  - `job_rule`：求职规则（薪资、地点、加班等）
  - `agent`：Agent 行为配置（并发数、自动回复开关等）
  - `reply_style`：回复风格参数
- **迁移历史**：0002 STEP 4.1 回填时使用过 `category='legacy'`，故历史数据中可能出现该值；迁移中的 CHECK 约束也包含了它。
- 该表**无 `created_at`**（与 Mixin 不同），只有 `updated_at`，符合「配置覆盖即更新」语义。
