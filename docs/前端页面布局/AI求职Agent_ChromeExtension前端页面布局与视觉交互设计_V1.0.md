状态，因此文档中会明确页面需要的数据。

# 2. 产品前端定位

AI求职Agent不是普通的聊天插件。

前端应该让用户感觉自己打开的是一个：

> **AI求职自动化控制中心**

用户不需要理解 LangGraph、MCP、Skill、Tool 等底层实现。

用户只需要知道：

1.  Agent现在是否运行。
2.  Agent现在正在做什么。
3.  Agent处理了哪些HR。
4.  有没有需要自己确认的事情。
5.  有没有错误。
6.  是否正在后台监听。
7.  自动回复、自动投递是否开启。
8.  当前任务进展如何。

# 3. 视觉基准

用户提供的总览图作为 V1 视觉基准。

整体采用：

-   深色左侧导航
-   浅色内容区域
-   白色卡片
-   蓝色主操作色
-   绿色运行状态
-   黄色/橙色提醒
-   红色错误
-   圆角卡片
-   高信息密度
-   类桌面工作台布局

整体视觉目标：

> **专业、可靠、清晰、有AI工具感，而不是传统后台管理系统。**

# 51. 前端与Agent状态的关系

前端不能自行猜测Agent状态。

例如：

不能因为按钮点击就直接显示：

``` text
运行中
```

应该由后端/Runtime状态驱动。

统一状态：

``` text
Backend / Agent Runtime
        ↓
WebSocket / API
        ↓
Pinia
        ↓
Vue UI
```

这样可以避免：

UI显示"运行中"，实际上Agent已经停止。

# 52. 实时事件数据

前端实时事件统一结构：

``` text
event_id
event_type
timestamp
task_id
conversation_id
title
description
level
```

前端只负责展示。

不在前端判断Agent逻辑。

# 53. UI核心原则

第一原则：

> 用户必须知道Agent现在在做什么。

第二原则：

> 用户必须知道Agent为什么需要自己确认。

第三原则：

> 用户必须可以随时停止Agent。

第四原则：

> 错误必须可解释。

第五原则：

> UI不能暴露不必要的技术复杂度。

第六原则：

> 普通消息自动处理，关键决策明确提醒用户。

第七原则：

> 页面视觉必须服务于Agent可观察性，而不是装饰。
