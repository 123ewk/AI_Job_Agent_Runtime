# 06 · 人工确认与长期记忆模块

## 模块说明

`approvals` 处理敏感信息的**人工确认**（20 秒提醒机制，`expires_at`），`memory` 存储求职过程**长期记忆**（pgvector 语义检索 Top-K 注入 Planner）。

## 表总览

| 表名 | 说明 | 主键 | 关键约束 |
|------|------|------|----------|
| `approvals` | 敏感信息人工确认 | id | CHECK(status)、部分索引 |
| `memory` | 长期记忆 + 512 维向量 | id | CHECK(type)、向量索引 |

---

## 表 1：`approvals`

> 人工确认模型。敏感字段：`salary` / `location` / `start_date` / `overtime` / `outsourcing` / `offsite` / `probation_salary`。20 秒提醒机制对应 `expires_at`。状态：`pending` / `approved` / `denied` / `timed_out`。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `task_id` | BIGINT | N | — | 关联任务，外键 |
| `user_id` | BIGINT | N | — | 需要确认的用户，外键 |
| `type` | VARCHAR(50) | N | — | 确认类型（见备注） |
| `payload` | JSONB | N | `'{}'::jsonb` | 待确认上下文数据 |
| `status` | VARCHAR(20) | N | `'pending'` | 状态，CHECK 约束 |
| `decision` | VARCHAR(20) | Y | — | 决策结果：`approve` / `deny` / `timeout`（冗余于 status，便于快速读） |
| `decided_at` | TIMESTAMPTZ | Y | — | 决策时间 |
| `expires_at` | TIMESTAMPTZ | Y | — | 过期时间（20 秒提醒对应点） |
| `reminder_count` | INTEGER | N | `0` | 已提醒次数 |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间（TimestampMixin） |
| `updated_at` | TIMESTAMPTZ | N | `now()` | 更新时间（TimestampMixin） |

### 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| `ix_approvals_task_id` | NORMAL | `task_id` | FK 反查 |
| `ix_approvals_user_status` | NORMAL | `(user_id, status)` | 用户待办列表 |
| `ix_approvals_expires_pending` | **部分索引** | `expires_at` | `WHERE status = 'pending'`，加速超时扫描 |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `ck_approvals_status` | CHECK | `status IN ('pending','approved','denied','timed_out')` |
| `fk_approvals_task_id` | FOREIGN KEY | `task_id → tasks.id` |
| `fk_approvals_user_id` | FOREIGN KEY | `user_id → users.id` |

### 关联关系

- **N:1** → `tasks`（`task_id`）、`users`（`user_id`）

### 备注

- `type` 枚举（doc 14 敏感信息分类）：`salary`（薪资）/ `location`（地点）/ `start_date`（入职时间）/ `overtime`（加班）/ `outsourcing`（外包）/ `offsite`（驻场）/ `probation_salary`（试用期薪资）。
- **部分索引**：超时扫描 `SELECT ... WHERE status='pending' AND expires_at < now()` 只扫未决行，避免全表；终态行被索引自动排除。
- `decision` 与 `status` 冗余并存：`status` 是权威状态，`decision` 是决策动作的快捷读（`approve`/`deny`/`timeout`），写时需同步维护。
- 迁移 0002 状态值：`REJECTED → denied`、`EXPIRED → timed_out`。

---

## 表 2：`memory`

> 长期记忆模型。存储求职过程中的长期上下文，按 user 维度 + 可选 conversation/job 关联。pgvector 语义检索 Top-K 注入 Planner。类型：`preference`（用户偏好）/ `hr_pact`（HR 潜规则/约定）/ `interview`（面试经验）/ `decision`（决策记录）/ `fact`（事实信息）。

### 字段定义

| 字段 | 类型 | NULL | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `id` | BIGINT | N | autoincrement | 主键 |
| `user_id` | BIGINT | N | — | 所属用户，外键，CASCADE 删除 |
| `conversation_id` | BIGINT | Y | — | 可选关联会话，外键 |
| `job_id` | BIGINT | Y | — | 可选关联岗位，外键 |
| `type` | VARCHAR(30) | N | — | 记忆类型，CHECK 约束 |
| `content` | TEXT | N | — | 记忆内容 |
| `embedding` | VECTOR(512) | N | — | 512 维向量（bge-small-zh），用于语义检索 |
| `created_at` | TIMESTAMPTZ | N | `now()` | 创建时间 |

### 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| `ix_memory_user` | NORMAL | `user_id` | 按用户过滤 |
| `ix_memory_user_conv` | NORMAL | `(user_id, conversation_id)` | 按用户+会话过滤 |
| `ix_memory_embedding` | IVFFLAT（向量） | `embedding` | `vector_cosine_ops`，`WITH (lists = 100)` |

### 约束

| 约束名 | 类型 | 定义 |
|--------|------|------|
| `ck_memory_type` | CHECK | `type IN ('preference','hr_pact','interview','decision','fact')` |
| `fk_memory_user_id` | FOREIGN KEY | `user_id → users.id`，`ON DELETE CASCADE` |
| `fk_memory_conversation_id` | FOREIGN KEY | `conversation_id → conversations.id` |
| `fk_memory_job_id` | FOREIGN KEY | `job_id → jobs.id` |

### 关联关系

- **N:1** → `users`（`user_id`，CASCADE）、`conversations`、`jobs`

### 备注

- **该表无 `updated_at`**：长期记忆是追加式知识，过期/错误记忆靠删除或新建，不做就地编辑。
- 语义检索路径：`user_id` 过滤 + `embedding <=> 查询向量`（cosine 距离）Top-K，结果注入 Planner 作为上下文。
- 记忆粒度建议：一条记忆一个原子事实，避免大块文本降低检索召回精度。
- 向量索引与 `resume_summaries` 同款（ivfflat / lists=100）；数据量增长后评估 `hnsw`。
